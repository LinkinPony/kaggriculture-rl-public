# Business Plan Strategy

This document describes the historical production path and model/executable components that are still in use. The new mainline entry points are `kagg-revue` / `python -m kagg_revue.learning.cli`, starting from entirely random weights, see [CURRENT_MAINLINE.md](CURRENT_MAINLINE.md). The old weights and teacher training commands mentioned in this document are no longer part of the new mainline.

Historical entry is `kagg-revue-production` or `python -m kagg_revue.production.cli`.
Initial teacher capability transfer uses [work.yaml](../configs/production/work.yaml); credit estimation for stopped credits uses [work_neural_credit.yaml](../configs/production/work_neural_credit.yaml). Daily replay BC uses [work_daily_bc.yaml](../configs/production/work_daily_bc.yaml).
Current decisions, frozen models, and evidence are available in [CURRENT_MAINLINE.md](CURRENT_MAINLINE.md); model sizes, expanded parameters, and measurement values are based on artifacts in the run directory.

## Decision and Execution

work-v1 outputs an ordered job queue per unit, as well as explicit market orders over each turn within the execution interval.
A job includes destination, operation, quantity, and earliest execution time; the native executor is responsible for moving and maintaining the queue cursor.
Market orders retain the order, quantity, and request timing for buy, sell, hire, and land acquisition operations, with strategies directly controlling inputs and transactions.
The old space land plan remains loadable and can be used as a reference point for existing checkpoints.

Neural strategies only replace the full plan at calendar boundaries; the executor advances turn by turn according to official rules. After reaching the destination, the executor waits for the job release moment, skips completed or deterministically invalid maintenance/harvesting tasks, and invokes shared official units in sequence. Full market requests are handed over to the official rule executor. Batch training and persistent sessions that only read official observations share the same compiler; repeatedly reading the same turn's action does not re-advance the queue.

The Actor uses an existing entity Transformer to encode both sides' territories, visible units, goods, stores, and public history; the opponent's hidden inventory remains invisible. After encoding, decoding is performed in device memory in sequence according to queue order and field dependencies; during the market phase, the aggregated work plan is read. Individual units can pre-arrange work for units to be hired subsequently. The current work-v1 also samples potential work for absent units and influences market output through aggregation; this introduces additional burdens for exploration and credit allocation, representing an interface still requiring reconstruction in the new mainline. All movement directions are generated by the compiler.

The first STOP corresponds to the end of a queue or market request in a turn. Subsequent padding fields, unused quantity fields, idle operation timestamp fields, and trailing padding turns do not participate in training loss. BC and PPO reconstruct the conditional probability of prior actions using real prior choices; sampling and replay use the same field support set.

## Teacher Transmission and Training

The original teacher is responsible for generating demonstrations and acting as the opponent. The label compresses moves in the demonstration into destinations, preserving the order of operations, incomplete move endpoints, and market requests. The label is a non-causal proposal based on the teacher's subsequent behavior; the Actor's input contains only the visible state within decision boundaries. Full replay responses in seed/seat/opponent contexts answer whether the teacher's capabilities can be preserved, while independent causal strategy competitions determine whether the strategy would use such language.

The original ZIP replay and reusable mmap shards preserve both source and content fingerprints. Daily BC performs bulk encoding of complete replays via persistent native sessions, pairing current observations with actions from the next record; unit actions are normalized using the official shared compiler, retaining exact counts from the request vocabulary. Both seats remain within the same training, validation, or test partition, with no repeated seeds across partitions. At each turn, the training shards and rows are randomly shuffled; NLL is used solely to measure proposal fit, while full game outcomes determine quality.

The Actor of daily BC does not include a time-indexed action table based on global time nor performs frequency table initialization; instead, it directly fits the mapping of conditional job scheduling. Time remains part of the environmental state, and the moment of job release still belongs to the semantic meaning of actions. The original teacher's frequency table and its parameters are used solely for existing control models. Trained weights and untrained baselines should be clearly distinguished; if the competition selection still retains epoch 0, `best.pt` must not be mistakenly referred to as the starting point of the trained BC.

Credit estimation is compared against pure self-play; plans are re-evaluated and revised every 4 official turns. Both self-play agents execute actions randomly according to the current policy, retaining the trajectory of each side, with each perspective assigned half the weight. Scripted opponents are not invoked during training or evaluation of this baseline. Advantage statistics, losses, and gradients are synchronized across ranks. Each plan shares the pure terminal WDL reward from the game; the critic independently observes the public state and the plan prefix prior to the current action selection, without backpropagating value gradients to the actor.

`prefix_trace_lambda=0` retains a historical estimate of the difference between adjacent values, `=1` uses full returns minus prefix values; intermediate values accumulate multi-step trajectories according to valid fields, skipping fields filled with padding or after STOP. This follows the [bias-variance trade-off in GAE](https://arxiv.org/abs/1506.02438). The first on-policy gradient of full returns does not require the downstream critic to be accurate, but this does not guarantee that multiple updates of finite-sample PPO improve full-game performance.

The ratio field of the PPO pruning condition is accumulated with an advantage, and KL is also accumulated based on valid fields; the old complete plan and field-wise surrogate are still used for explicit historical baselines. The loss cannot be divided by the number of valid fields in the sampling plan, otherwise changes in length caused by STOP would introduce biased gradients in the state baseline. Selection is sorted by `wins - losses`, and ties are broken without cash advancement. Cash and cash differences are for diagnostic purposes only.

Evaluation focuses on `production/evaluation/`. `evaluation_policies` can specify freezing of neural checkpoints, and optionally splits the full game and seat equally between scripts. Opponents make real-time decisions based on their own observable observations, reporting their identity via the checkpoint SHA-256 hash; evaluation restores the caller's RNG without consuming training sampling streams. When only a neural opponent is configured, no old notebook manifest or teacher source code is read. Two seats share a seed, so confidence intervals for paired comparisons are sampled by seed group.

`ppo.temperature` specifies a fixed sampling temperature for each condition distribution. Sampling, device behavior probabilities, learner's likelihood reweighting, and entropy all use the same temperature; the ratio and KL of the complete plan thus compare distributions with the same definition. A positive temperature does not alter the ordering of greedy actions. Independent random evaluation uses the temperature from the expansion configuration, while greedy evaluation still takes argmax per field; reports separately record the execution method and sampling temperature.

## Runtime Boundaries

Each GPU bears a full game shard and one synchronous learner rank. The Actor uses a fixed-shape CUDA Graph, with conditional decoding completed in a single device call, returning only the plan required for native execution in the next segment. After releasing the GIL, native batching advances the full interval, with observation and action probabilities written to the device tape; the learner collects bounded microbatches by index. Parameter conversion must be completed within the captured graph to ensure that each replay of the graph reads the current weights after optimization.

Run `python -m kagg_revue.production.cli production=work_neural_credit` in a named tmux session.
This configuration declares a limited diagnostic window and is not suitable as a validated long-term training protocol. Reproducing the experiment should use a new output directory; continuing training requires explicitly specifying a complete PPO checkpoint, preserving the optimizer and per-rank RNG, and setting the target update as needed.
Changing the work schedule calendar requires re-extracting labels; work queues with time stamps cannot reuse prior interpolation from old plot plans.

Associated windows within the same tmux session can run
`python -m kagg_revue.production.completion production=work_neural_credit`, and after full training completion, independent confirmations are performed sequentially on the best, final, and frozen baseline; each model separately records the random and greedy expansion configurations and identities. This task reports only the direct game results and does not automatically promote or deploy models.

`production.mode=audit` checks teacher language transmission;
`evaluate` runs independent pairing for explicit checkpoint;
Game, `evaluation_sample` may optionally execute randomly;
`reference` uses frozen official interpreter to verify two seats' full season and per-turn budget. A large number of evaluations use equivalent native/GPU batches, while official process execution is performed solely for semantic and budget verification. Short-term updates, independent win validations, and official semantic checks each address different questions and none can replace formal submission for advancement.
