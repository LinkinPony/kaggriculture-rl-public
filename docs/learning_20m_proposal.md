## Design Basis

The current grounded model has approximately 1.595M parameters and has reused features from the previous entity encoding, including land, units, goods, stores, and public history. The 384-dimensional, 6-layer backbone of the original production model provides a reference for expansion, but reverting to the old configuration alone will not introduce these existing features. The new approach primarily increases representation depth, enhances executability and short-term history, and redesigns the decoder for the current action interface.

See [Parameter Count](../outputs/analysis/grounded-v2-20260908/parameters.json).

Apply a shared lightweight 3×3 depthwise convolution with channel projection on the land token of two farms, then proceed to global entity attention. This establishes a direct representation path between adjacency relationships and local production layouts, while preserving interactions among land, workers, goods, and global economic states.

The actor's unit action follows the "position pointer → operation → quantity" pattern: workers match against candidate land representations to achieve the target. The operation and quantity are generated by output heads of clearly defined types, and continue to use validity masks.
The market retains at most 10-order condition sequences, with operations affecting the distribution of quantities.
A shared conditional decoding module and typed selection embeddings are employed, and the long-task output parameters used in the current single-turn interface are removed.
The existing native program external layout is preserved, and fields not involved in strategy loss are filled.

Critic uses a separate encoder to output both V(s) and V(s, prefix of the selected action). The prefix encoder only reads fields prior to the current action and does not read future actions; it is compatible with the credit assignment mechanism of the current prefix PPO.

## Features

Retain the existing visible entity characteristics, and specifically supplement:

- 44-bit support information and visibility flags for actions a unit can perform. Current support information is primarily used for action masks, and the new model also uses it as input to allow the representation layer to pre-know what actions are possible.
- Production time information derived from the current public state and rules: maturity, harvest, maintenance time windows, as well as a summary of the unit's backpack, warehouse, and harvestable outputs.
- Public market and economic changes on turn scales of 1, 4, 12, and 24, encoded as 4 historical tokens; reuses existing C++ history buffer, increasing the maximum token count from 282 to 286.

All newly added information is derived from the visible state and historical computations. Training, replay BC, and deployment use the same native C++ encoding path, with new feature versions registered; opponent private information is handled using visibility markers.
The old BC arrays must be re-encoded and cannot be directly fed as input to the new feature version.
The actual observation width is 13,316, with 1,800 new native context items added; detailed layout see [Feature and Action Interface](grounded_context.md).
